# Implementation Plan: TypeScript Database Schema Alignment

## Overview

This implementation plan addresses the alignment of TypeScript type definitions, action functions, and validation logic with the PostgreSQL database schema after SQL compatibility fixes. The implementation follows a layered approach: first updating type definitions to match the database schema, then creating a central mapping utility layer, updating action functions to use the mapping layer, and finally updating validation logic. Each step builds incrementally to ensure type safety and backward compatibility throughout the migration.

## Notes

- Tasks marked with `*` are optional and can be skipped for faster MVP
- Each task references specific requirements for traceability
- The mapping layer (task 2) is critical and must be implemented before action function updates
- Type definitions (task 1) should be completed before mapping layer to ensure type safety
- Validation updates (tasks 6-7) are independent and can be done in parallel with action updates after mapping layer is complete
- Computed column property tests (task 8) require database access and verify database-level behavior
- All transformation functions centralized in `lib/actions/utils/mapping.ts` for consistency
- Checkpoints ensure incremental validation at key milestones
